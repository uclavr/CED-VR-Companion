# CED VR Companion

This program is designed to be used alongside CED VR by UCLA Physics. Refer to https://github.com/cms-outreach/ispy-analyzers for information regarding how to create a '.ig' file using CMSSW.

This program works by unzipping and parsing the ig file, producing obj (geometry data) and json files, and sending these to the headset via the Android Debug Bridge. These files will be automatically found and used by our event display which you can download here: https://www.meta.com/s/4YdsvzpbH. 

This project is part of the work being done by the UCLA VR Group. You can check out more projects here: https://vr.physics.ucla.edu/index.html

The master branch of this repository is designed to be used by macOS. If you are using Windows, use the Windows branch.

## Quick Start

### Command Line Use 

1) Clone the repository
2) Connect your headset (Quest 2 & Quest 3 are supported) and enable USB Debugging and Developer Mode on the headset
3) Go to bin/Debug/net8.0 and run the following command
```
./CED\ VR\ Companion path_to_ig_file [options]
```
CED VR Companion accepts 2 arguments (the path to your '.ig' file and option flags) when being called from the command line. An interface will display allowing you to select your desired run. After execution, the event files will be automatically uploaded to your headset. 

### Options
- 's': Allows you to select a single event from the run
- 'c': Allows you to select a range of events from the run
  
### Example Usage with Sample Data
```
./CED\ VR\ Companion DoubleMuParked_Run2012C_0.ig
```
## Common Issues

**Issue:** "Unhandled exception. System.ArgumentNullException: Value cannot be null. (Parameter 'device')"
**Solution:** Make sure that the headset is plugged in and that USB debugging and Developer Mode is enabled on the headset
### ADB  

CED VR Companion utilizes the Android Debug Bridge to communicate with Oculus devices. Please make sure your Oculus Quest device is connected with developer mode enabled before running the companion. ADB is already installed with the executable and is located in platform-tools. The program uses a hardcoded path to platform-tools/adb so do not move this folder around. 

## ISpy Analyzers & Generation of IG Files

CEDVR uses `.ig` files generated by the [CMS iSpy Analyzers](https://github.com/cms-outreach/ispy-analyzers) to visualize collision events. To correctly represent the calorimeter segmentation in CEDVR's LEGO plots, we have modified two of the original analyzer files: `ISpyEERecHit.cc` for AOD and `ISpyPackedCandidate.cc` for MiniAOD.

These modifications are available in our [CEDVR-compatible iSpy Analyzers fork](https://github.com/nathan-joshua/ispy-analyzers/tree/cedvr-cmssw15).

#### ECAL Segmentation

The segmentation of the Electromagnetic Calorimeter (ECAL) differs from that of the Hadronic Calorimeter (HCAL).

In the ECAL Barrel (EB), covering $|\eta| < 1.479$, individual ECAL crystals have approximately uniform granularity of $\Delta\eta \times \Delta\phi \approx 0.0174 \times 0.0174$. Up to HCAL tower 17, groups of $5 \times 5$ ECAL crystals form trigger towers that approximately align with HCAL tower boundaries.

In the ECAL Endcap (EE), however, crystal segmentation varies with position and does not match HCAL segmentation one-to-one. Consequently, CEDVR uses different approaches for AOD and MiniAOD data.

**AOD**

AOD provides individual ECAL rechits, allowing CEDVR to display energy deposits at crystal-level granularity.

For the ECAL Endcap, we modified `ISpyEERecHit.cc` to use CMSSW's `CaloSubdetectorGeometry` interface to obtain the effective $\Delta\eta$ and $\Delta\phi$ associated with each crystal.

These values are stored as additional properties in the `EERecHits_V2` collection of the generated `.ig` files, allowing CEDVR to render EE energy deposits with the appropriate variable segmentation. For EB rechits, CEDVR uses the approximately uniform crystal granularity.

**MiniAOD**

Unlike AOD, MiniAOD does not retain the complete collection of individual ECAL crystal rechits. The existing iSpy `ISpyPackedCandidate.cc` analyzer instead constructs a coarser calorimeter representation from packed particle-flow candidates, associating them with calorimeter regions using detector geometry.

We extended this analyzer to compute the effective $\Delta\eta$ and $\Delta\phi$ of these regions using the $\eta$ and $\phi$ coordinates of their representative corners. These values are stored as additional properties in the existing `EcalTowers_V1` and `HcalTowers_V1` collections and exported to the `.ig` files.

CEDVR subsequently uses the exported segmentation values to determine the dimensions of the calorimeter energy deposits in its LEGO plots. The resulting MiniAOD representation is coarser than the crystal-level visualization available with AOD.

#### Required Analyzer Modifications

Users with an existing, compatible iSpy analyzer installation do not need to clone our entire fork. Instead, they can replace the relevant source files with the modified versions linked below.

| Data tier | File to replace | Modification |
|---|---|---|
| AOD | [ISpyEERecHit.cc](https://github.com/nathan-joshua/ispy-analyzers/blob/cedvr-cmssw15/src/ISpyEERecHit.cc) | Adds per-crystal `deltaEta` and `deltaPhi` to `EERecHits_V2`. |
| MiniAOD | [ISpyPackedCandidate.cc](https://github.com/nathan-joshua/ispy-analyzers/blob/cedvr-cmssw15/src/ISpyPackedCandidate.cc) | Adds geometry-derived `deltaEta` and `deltaPhi` to `EcalTowers_V1` and `HcalTowers_V1`. |

The modifications were written for CMSSW version 15.0.16. Compatibility with older CMSSW releases or analyzer versions is not guaranteed.

**To apply the modifications:**

1. Navigate to the source directory of your existing iSpy analyzer installation:

   ```bash
   cd CMSSW_15_0_16/src/ISpy/Analyzers/src
   ```

2. Back up the relevant original files:

   ```bash
   cp ISpyEERecHit.cc ISpyEERecHit.cc.bak
   cp ISpyPackedCandidate.cc ISpyPackedCandidate.cc.bak
   ```

3. Download the modified files:

   ```bash
   curl -fL https://raw.githubusercontent.com/nathan-joshua/ispy-analyzers/cedvr-cmssw15/src/ISpyEERecHit.cc -o ISpyEERecHit.cc

   curl -fL https://raw.githubusercontent.com/nathan-joshua/ispy-analyzers/cedvr-cmssw15/src/ISpyPackedCandidate.cc -o ISpyPackedCandidate.cc
   ```

   Users working exclusively with AOD or MiniAOD may replace only the corresponding file.

4. Rebuild the analyzers from the CMSSW `src` directory:

   ```bash
   cd ../../..
   cmsenv
   scram b -j 4
   ```

After rebuilding, generate `.ig` files using an appropriate AOD or MiniAOD configuration, ensuring the corresponding analyzers are enabled.

The resulting `.ig` files can then be processed using the CEDVR Companion parser and visualized in CEDVR.
